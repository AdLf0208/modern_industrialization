# Working on Modern Industrialization (Horizon native mod, SDK format)

> **Build slots:** every build/test/check goes through the campaign runner
> (`../tools/build-slot.sh run --job sdk-mi --port ports/modern_industrialization --step check --
> cargo horizon-mod check`, run from this port). It **blocks in the kernel** until a slot is free —
> never poll, never background a build and end the turn. Use `BUILD_LOCAL=1`: the SDK path needs
> `.horizon/sdk`, the `wasm32-unknown-unknown` target and the SDK's own toolchain, which the second
> box does not have, so forwarding cannot work here. A timeout exits **75**; read
> `../_shared/build-slots-usage.md` first.

Read `README.md`, `notes.md` (especially §Migration to the SDK format) and `VALIDATION.md` before
editing. This port is **one flat SDK package** (mod API `0.2`, pin `0b14f8a`); the retired
`.hnmod` container — `mixins/`, `horizon-mixin.toml`, `horizon-native.json`, `content/`,
`compatibility.json`, `rust-toolchain.toml`, `tools/horizon.py` — must **not** be recreated.

- **`src/runtime.rs` is the pure core** — no `mod_api` types, no I/O — and holds the recipe table,
  generated by `tools/carry_recipes.py` from the pack jar: never hand-edit a row, change the
  selection and regenerate. It is covered by `cargo test`. The migration fixed it as
  **byte-identical** (SHA-256 `0f3b451a…`); on 2026-11-20 its local type `Recipe` was renamed
  `MaceratorRecipe` (in the generator too) so `uses.json` stops recording it as the SDK
  `type:Recipe` — the logic and every row are unchanged. Slice 4 (2026-11-21) added the
  `HatchTier`/`HatchKind::EnergyHatch` family and `move_energy_count`, tests first; current
  SHA-256 `12d83961…ebc9d0`. Treat a change to it as a slice of its own, with its tests written first.
- **`src/lib.rs` is the glue**: `impl Hooks::register` declares the block entity type and the
  block's two capabilities, the Part (`impl BlockEntityPart for Machine`) answers the machine's
  moments, and the command is `register_commands` + `run_mod_command`. No business rules here —
  they belong in the runtime with a test.
- A moment that belongs to **one** block entity type is a **Part** method, not a global hook.
  `horizon-mod.toml` is the only manifest; `[native]` is the pin.
- `assets/` and `data/` are the carried content of this same package (`capabilities =
  ["registries"]`): no embedded `.hmod`, no `content_root` injection, no `.horizon-cache`.
- The delivered package is `modern_industrialization.hmod` in the port root; `target/` and
  `.horizon/` are disposable. What sits in the package root ships, so `README.md` is user-facing.
- Validate with `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings`, `cargo test`,
  then `cargo horizon-mod check`, `build`, `check <hmod>` and `fits <hmod>` through the runner, and
  record the sha256 in `VALIDATION.md`. The in-game leg is live again: build the launcher game
  (`ports/tools/launcher-game.sh build modern_industrialization`) and run `tools/e2e.sh` through
  `build-slot.sh run --step e2e`; it honours `E2E_TMP` so its scratch world stays off the `/tmp`
  tmpfs.
